# Meet 字幕フルスクリーン

Google Meet の**字幕エリアだけをブラウザ画面いっぱいに拡大表示**するブックマークレットです。
Meet 標準の字幕は数行で流れて消えてしまうため、字幕を大きく表示しつつ**過去の発話を履歴として蓄積**します。

## インストール

**→ [インストールページを開く](https://yugo-yamamoto.github.io/meet-caption-fullscreen/)**

開いたページの青いボタンを**ブックマークバーへドラッグ＆ドロップ**してください。

> [!NOTE]
> GitHub は README 内の `javascript:` リンクをサニタイズして無効化するため、
> ドラッグ用のリンクはこの README には埋め込めません。上記の GitHub Pages 上のページから登録してください。
> ドラッグを使わない場合は [`bookmarklet.txt`](bookmarklet.txt) の中身をコピーし、
> ブックマークマネージャで新規ブックマークの URL 欄に貼り付けてもインストールできます。

## 前提: 字幕の ON と言語設定は Meet 側で行ってください

> [!IMPORTANT]
> **このツールは Meet の設定を一切変更しません。** 字幕(CC)の ON/OFF と、字幕の言語
> （`字幕設定を開く` → `会議の言語`）は、利用者が Meet 側で設定してください。
>
> 字幕を出すには「CC を ON にする」だけでは足りず、**会議の言語が実際に話す言語と一致している**
> 必要があります。英語設定のまま日本語で話すと、CC が ON でも字幕はほとんど出ません
> （実機検証中にこれで詰まりました）。言語の選択は状況によって変わるうえ、会議中の表示に
> 影響する操作なので、ツールが勝手に切り替えるべきではないと判断しました。
>
> このツールがするのは「Meet が表示している字幕を読み取って大きく見せる」ことだけです。

## 使い方

1. Google Meet で会議に参加する
2. **Meet 側で字幕(CC)を ON にし、`字幕設定を開く` → `会議の言語` を話す言語に合わせる**
3. ブックマークバーの「Meet 字幕フルスクリーン」をクリック
4. 終了は <kbd>Esc</kbd>、「閉じる」ボタン、またはブックマークを再クリック（トグル）

ブラウザの Fullscreen API は使わず、ページ内のオーバーレイ（`position: fixed`）として最大化します。
Meet 本体はオーバーレイの裏で動き続けるため、退出やミュートはオーバーレイを閉じてから操作してください。

## 機能

| 操作 | 内容 |
| --- | --- |
| `A-` / `A+` | 文字サイズ変更（`localStorage` に保存し次回も再現） |
| `全文コピー` | 「話者: 発言」形式の全履歴をクリップボードへ |
| `履歴クリア` | 蓄積した発話履歴を破棄 |
| `ログ表示` / `ログコピー` | 検出状況・動作ログの確認とコピー（不具合報告用） |
| `閉じる` | オーバーレイを終了（<kbd>Esc</kbd> でも可） |

- 字幕の ON/OFF と会議の言語は Meet 側で操作してください（このツールは Meet のボタンを押しません）
- 起動時に会議の言語をログに出します。話す言語と違う場合は警告を出しますが、**変更はしません**
- 発話中の行はリアルタイムに書き換わり、確定済みの発話は履歴として残ります
- 上へスクロールすると自動追尾を停止し、最下部に戻すと再開します

## 実装メモ

### Meet の CSP (Trusted Types) 対応

Meet は `require-trusted-types-for 'script'` を強制しているため、`innerHTML` への代入は
`This document requires 'TrustedHTML' assignment.` でブロックされます。そのため

- UI は `createElement` / `textContent` のみで構築（`innerHTML` 不使用）
- CSS はインライン `<style>` ではなく CSSOM の `sheet.insertRule()` で注入（`style-src` 制限を回避）
- さらに `element.style` で最低限のレイアウトを二重に適用し、CSS が全滅しても崩れないようにしています

### 会議の言語（字幕が出ない最大の原因）

Meet の「字幕設定を開く」にある **`会議の言語`** が話している言語と違うと、字幕を ON にしても
ほとんど何も出ません（英語設定のまま日本語で話すと、たまに英語として誤認識された断片が出るだけ）。
実機検証中に実際にこれで詰まったため、起動時に必ず言語をログへ出します。
UI が日本語なのに会議の言語が日本語でない場合は警告を出します。

**読み取って知らせるだけで、設定は変更しません。** 言語の切り替えは Meet 側で行ってください。

```
[12:32:34] 注意: 会議の言語が「英語」です。日本語で話しても字幕が出ません。
           Meet の「字幕設定を開く」から会議の言語を日本語に変更してください。
```

### 字幕コンテナの検出（難読化クラス名を使わない）

実測した Meet の DOM（2026-08 時点）:

- 字幕エリアは `div[role="region"][aria-label="字幕"]`。**内側に `aria-live` は無い**
- 発話行はそのリージョンの**直下**（`div.nMcdL` 相当）。行の中はアバター `img[alt=""]` と
  話者名 `span` が同じ親に入り、本文は兄弟の `div`
- リージョン直下には発話行のほかに非表示の空 div と「最新の字幕に移動」ボタンが並び、
  ボタン内には `aria-hidden="true"` のアイコン文字（`arrow_downward`）と
  ツールチップ文字（`一番下に移動`）が入っている

判定は**1 経路だけ**です。以前は「部分一致 → `aria-live` フォールバック → `role=region` 推測」と
段階的なフォールバックを持っていましたが、実機で分岐カバレッジを計測したところ**一度も実行されず**、
誤検出の原因にしかなっていなかったため削除しました（下記「分岐カバレッジ」参照）。

1. **コンテナ**: `[aria-label]` を走査し、`^(字幕|キャプション|captions?|subtitles?)$` に
   **完全一致**する最初の要素。実測では一致する要素はページ内に 1 個だけで、
   ボタン類（`字幕をオフにする` / `字幕設定を開く` / `字幕の種類`）は完全一致しないため除外処理は不要
2. **発話行**: コンテナ直下の子要素のうち、本文テキストを持つもの
3. **本文の抽出**: 行内の「テキストを持つ末端要素」を文書順に集め、
   `aria-hidden="true"` の内側と `button` / `a` / `[role="button"]` の内側は除外
   （これを入れないとジャンプボタンの `arrow_downward` / `一番下に移動` を発話として表示してしまう）
4. **話者名**: 先頭の末端要素が**アバター画像と同じ枝にある**なら話者名
   （実測では `img` と名前 `span` が同じ親。`alt=""` なので alt では判定できない）

見つからない場合は推測せず、8 秒後に案内を出します。

### 分岐カバレッジ（実機計測）

すべての分岐にカウンタを入れた版を CDP で実会議に注入し、60 秒間発話して計測しました。

| 実行された分岐 | 回数 |
| --- | --- |
| `aria-label` 完全一致でコンテナ検出 | 1 |
| `^字幕$` に一致した要素数 | 1（＝除外フィルタは結果に無影響） |
| 行の起点＝コンテナ自身 | 91 |
| 話者名＝アバター枝で判定 | 91 |
| 継続判定（伸長 / 共通接頭辞） | 2 / 5 |
| 会議の言語チェック | 1 |

一度も実行されなかった分岐（部分一致、`aria-live` フォールバック、アナウンサー除外、
候補複数時の優先付け、操作系ラベル・操作系要素の除外、`aria-live` 起点、ラッパ掘り下げ、
30 文字ヒューリスティック、`img[alt]` 由来の話者名、`innerText` 分解、縮小判定、
切り離された行の統合、取りこぼし自己診断）は**すべて削除**しました。
結果、本体は 483 行 → 329 行になりました。

### 発話の重複排除

Meet は発話中の行の DOM ノードを再利用してテキストを書き換えるため、行要素そのものを `WeakMap` のキーにして
通し番号を振り、同じノードなら「更新」、初見なら「新規発話」と判定します。

ただし「同じノード = 同じ発話」とは限りません。Meet は行ノードを次の発話に再利用することがあり、
素朴に更新扱いにすると**前の発話が上書きされて履歴が消えます**。そこで、認識確定にあわせた
書き換えなのか別発話への差し替えなのかを、テキストの共通接頭辞で判定します。

- 新しいテキストが古いテキストで始まる（伸びた）、または共通接頭辞が 6 文字以上
  （もしくは短い側の 50% 以上）→ 同一発話の更新
- それ以外（先頭から別のテキストになった）または話者名が変わった → 別発話として新しいエントリに切り出す



## 開発

```bash
# ソースを編集したら再ビルド（bookmarklet.txt と docs/index.html を再生成）
uv run build.py
```

- `meet-caption-fullscreen.js` — 本体（編集はここだけ）
- `build.py` — コメント除去 → URL エンコード → `bookmarklet.txt` / `docs/index.html` を生成
- `docs/` — GitHub Pages 用のインストールページ（Settings → Pages で `main` / `docs` を指定）

### 実機（本物の Meet）での確認

`--remote-debugging-port=9222` で起動したブラウザに CDP で接続し、実際の会議 DOM に対して確認しました。

| 項目 | 結果 |
| --- | --- |
| 字幕コンテナの検出 | `aria-label 完全一致 ("字幕")` で成功 |
| Trusted Types / CSP | エラーなし。オーバーレイが正しく描画される |
| 話者名と本文の分離 | 実測構造の行を差し込んで成功（「最新の字幕に移動」ボタンや `aria-hidden` テキストは拾わない） |
| 認識確定による書き換え | 同一エントリの更新として処理 |
| 行ノードの再利用 | 別発話として切り出し、履歴を保持 |
| 実際の発話の取り込み | 成功。実会議で 60 秒間の日本語字幕を取り込み、Meet 側 315 文字とオーバーレイ 315 文字が**完全一致**（末尾テキストも同一） |
| 会議の言語の警告 | 成功（`会議の言語=英語` を検出して警告を表示） |

字幕が OFF のとき `[role="region"][aria-label="字幕"]` は DOM に存在せず、ON にすると現れます
（ON 直後は発話が無いのでテキスト量 0）。この状態では `[role="region"][aria-label="通話コントロール"]` が
最大のテキスト量を持つため、かつての `role=region` フォールバックはこれを掴んでいました（撤去済み）。

### 動作確認

Meet と同じ CSP を付けたローカルサーバーと、難読化クラスを持たない字幕 DOM シミュレータで検証できます。

```bash
uv run serve_csp.py 8765     # require-trusted-types-for 'script'; style-src 'self' を付与
# http://localhost:8765/test-meet-dom.html?autoclick
```

| クエリ | 検証内容 |
| --- | --- |
| `?autoclick` | ツールバー全ボタンを自動クリックして例外が出ないか |
| `?en` | 英語 UI（`aria-label="Captions"`）で検出できるか |
| `?ccoff` | 字幕 OFF 状態で誤検出せず、案内を出すか |
| `?recycle` | 行ノードが別発話に再利用されても履歴が上書きされないか |

ヘッドレス Chrome での確認例:

```bash
google-chrome --headless=new --screenshot=shot.png --window-size=1400,760 \
  "http://localhost:8765/test-meet-dom.html?autoclick"
```
